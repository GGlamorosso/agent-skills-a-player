# Protocole complet de raisonnement ontologique

## But

Transformer toute base de connaissances en système de réflexion, pas en machine à résumer des experts.

Les sources servent à :

- fixer les faits et les contraintes du réel ;
- fournir des modèles candidats et des questions fécondes ;
- opposer des contre-modèles, cas limites et contradictions.

Elles ne remplacent jamais la dérivation. Une autorité ne constitue pas un lien causal.

## Trigger

Utiliser ce protocole pour toute question non triviale :

- conceptuelle ou philosophique ;
- stratégique ou diagnostique ;
- causale ou prospective ;
- liée à une décision ;
- demandant d'arbitrer plusieurs doctrines ou experts.

Une recherche factuelle simple n'exige pas toute la structure.

## Inputs

- La question exacte et le résultat attendu : explication, décision, prédiction ou plan.
- Le contexte réel du projet, s'il existe.
- Les sources, notes et documents pertinents disponibles.
- Les contraintes, préférences et incertitudes connues.

## Procédure

### 1. Définir ce qui doit être expliqué

- Nommer l'objet, le système ou la décision.
- Définir les termes ambigus.
- Fixer le niveau d'analyse et l'horizon temporel.
- Distinguer la question descriptive (« que se passe-t-il ? »), causale (« pourquoi ? »), prédictive (« que va-t-il se passer ? ») et normative (« que faut-il faire ? »).

### 2. Chercher pour contraindre, pas pour recopier

Utiliser d'abord les index, manifestes, moteurs de recherche ou cartes de contenu disponibles. Ne charger que le plus petit ensemble de sources suffisant.

Pour une question importante, chercher quand ils existent :

1. les faits du projet ;
2. le meilleur modèle opératoire disponible ;
3. une perspective indépendante ;
4. un désaccord, une limite ou un cas d'échec ;
5. la preuve brute ciblée seulement si une prémisse décisive reste douteuse.

Deux sources qui répètent la même doctrine ne comptent pas comme deux perspectives.

### 3. Construire le registre épistémique

Séparer avant de conclure :

| Type | Question |
| --- | --- |
| Fait | Qu'est-ce qui est observé, mesuré ou documenté ? |
| Claim sourcé | Que soutient exactement une source nommée ? |
| Hypothèse utilisateur | Qu'est-ce que la question tient déjà pour vrai ? |
| Hypothèse agent | Quel pont faut-il supposer pour raisonner ? |
| Inférence | Qu'est-ce qui est déduit du modèle plutôt que lu dans une source ? |
| Inconnu | Quelle donnée pourrait inverser le verdict ? |

Ne pas étiqueter lourdement chaque phrase dans la réponse. Rendre ces catégories visibles lorsque leur confusion modifierait la conclusion.

### 4. Reconstruire l'ontologie

Décrire uniquement les éléments qui changent le raisonnement :

- **Entités et niveaux** : individu, groupe, entreprise, marché, institution, symbole, corps, conscience, etc.
- **Fonctions** : quel problème chaque élément résout-il ou quel rôle rend-il possible ?
- **Agents et actions** : qui peut choisir quoi ?
- **Finalités et payoffs** : qu'essaie réellement d'obtenir chaque acteur ?
- **Contraintes** : physiques, biologiques, économiques, institutionnelles, cognitives, morales et temporelles.
- **Information** : qui sait quoi, qui ignore quoi, qui peut signaler ou mentir ?
- **Relations** : dépendance, substitution, complémentarité, conflit, hiérarchie, feedback.
- **Temps** : état initial, transition, état futur ; effets de premier et de second ordre.

« Ontologique » ne signifie pas abstrait. Si une catégorie n'altère ni le mécanisme ni la décision, la retirer.

### 5. Formuler les modèles causaux concurrents

Pour chaque explication sérieuse :

1. prémisses ;
2. mécanisme ;
3. prédictions observables ;
4. conditions de validité ;
5. cas où elle échoue.

Classer les contradictions :

- données incompatibles ;
- définitions différentes ;
- causalités concurrentes ;
- objectifs ou valeurs incompatibles ;
- périmètres différents ;
- horizons temporels différents.

Ne pas « moyenner » deux modèles réellement incompatibles.

### 6. Dériver

Construire la chaîne la plus courte qui reste auditable :

```text
prémisses étayées
→ mécanisme
→ changement d'incitations, de contraintes ou d'état
→ réaction des autres éléments du système
→ conséquence de premier ordre
→ conséquence de second ordre
→ conclusion conditionnelle
```

Tester :

- la meilleure explication rivale ;
- le cas limite ;
- l'inversion d'une hypothèse centrale ;
- la réaction des autres agents si la stratégie réussit ;
- le signal qui falsifierait la conclusion.

### 7. Répondre

Commencer par la position ou le diagnostic. Donner ensuite :

1. la chaîne causale minimale ;
2. la contradiction décisive ou l'incertitude ;
3. la conséquence concrète ;
4. le test, la métrique ou l'action ;
5. les sources qui étayent les prémisses.

Adapter la forme à la question. Le protocole structure la réflexion ; il n'impose pas sept rubriques mécaniques.

## Interdictions

- Répondre par une liste de ce que disent plusieurs experts.
- Changer les mots d'une source et présenter cette reformulation comme une analyse.
- Utiliser un nom d'auteur comme preuve.
- Cacher une hypothèse contestable dans une transition logique.
- Ajouter « théorie des jeux », « ontologie » ou « dialectique » pour produire une impression de profondeur.
- Conclure « c'est complexe » sans identifier la variable ou le test qui tranche.
- Inventer un consensus ou une contradiction.

## Test anti-paraphrase

Avant de livrer :

1. Quelle partie de la conclusion a été réellement dérivée ?
2. Quel mécanisme relie les prémisses à cette conclusion ?
3. Quelle source ou observation soutient chaque prémisse décisive ?
4. Quelle hypothèse vient de l'agent ?
5. Quel contre-modèle a été testé ?
6. Qu'est-ce qui ferait changer d'avis ?

Si la réponse disparaît lorsqu'on retire les noms d'experts, ce n'est pas encore un raisonnement. Si elle ne change pas lorsqu'on retire toutes les preuves, c'est probablement une spéculation non contrainte.

## Exemples de contrôle

### Question business

Mauvaise sortie : « L'expert A recommande la niche, l'expert B recommande un SaaS vertical, donc le projet est intéressant. »

Bonne reconstruction : identifier le client, le problème coûteux, les substituts, l'unité économique, le canal, l'asymétrie d'information, les actions des concurrents et la dynamique si le marché devient visible ; dériver ensuite l'équilibre probable et le test le moins coûteux qui pourrait invalider le projet.

### Question philosophique

Mauvaise sortie : reprendre les conséquences célèbres associées à un auteur.

Bonne reconstruction : définir d'abord la fonction du principe supprimé, les niveaux qu'il reliait, les contraintes qu'il stabilisait et les mécanismes de remplacement disponibles ; dériver ensuite ce qui se fragmente, quels substituts apparaissent et sous quelles conditions la conséquence annoncée suit réellement.

## Output

Une réponse originale mais contrainte par le réel :

- conclusion claire ;
- dérivation causale vérifiable ;
- contradictions non lissées ;
- frontières entre preuve, hypothèse et inférence ;
- implication ou test concret ;
- sources attribuées.

## Quality Bar

La réponse ne doit être ni un résumé de littérature, ni une opinion libre. Elle doit produire une conclusion que les sources n'ont pas simplement énoncée, tout en permettant de remonter de cette conclusion jusqu'aux prémisses, aux preuves et aux hypothèses.
